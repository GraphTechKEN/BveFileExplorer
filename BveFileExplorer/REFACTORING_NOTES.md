## バグ修正

### データに影響するもの
- BVE6コンバータ: Shift_JIS の車両ファイルで、ヘッダ以外の全行が ":shift_jis" に置き換わっていた
- BVE6コンバータ / 車両解析: パスに "ats" を含む行(例 `Panel = Ats\panel.txt`)を Ats 行と誤判定していた → キー名で判定
- 選択マップで起動: Route に車両ファイルのパスを書き込んでいた
- 選択車両/マップで起動: `VehicleTitle` / `RouteTitle` 行も置き換えていた。Shift_JIS のシナリオを UTF-8 として読み書きしていた
- 選択車両/マップで起動: 不要なバックアップ(.bak / .tmp.txt.bak)を作成・削除していた(ユーザーの既存 .bak を上書き・削除する恐れ)→ 作成しない
- マップ解析: 判定したエンコードを使わずに読んでいた
- 車両/シナリオ解析: コメント行(; #)が除外されていなかった

### 落ちる・表示がおかしいもの
- サウンド/固定音源リスト: 備考付きで列数が多い行で例外
- グリッドのヘッダをクリック/ダブルクリックすると例外(車両/路線/他列車/停車場/サウンド各グリッド)
- 各グリッドの最終行、シナリオ一覧の先頭2行と最終行が色付けされない
- シナリオ一覧: 起動直後に先頭行をクリックしても開かない。フォルダ変更後に同じ行番号が開かない
- include 一覧: 先頭の include が表示されなかった。大文字の Include が除去されなかった
- Reset: サウンドリストのグリッド/エンコード表示がクリアされていなかった
- エンコードコンボの自動設定で同じファイルを二重に読み込んでいた
- シナリオフォルダの「開く」が親フォルダを開いていた
- マップの「開く」「フォルダ」が、マップを切り替えても1つ目のマップを開いていた
- サウンド再生停止ボタンのイベントが再生のたびに多重登録されていた
- 空ファイル、不正なパス、存在しない DetailManager.dll で例外
- 凡例ボタンのツールチップ(BVE6 が BVE5 ボタンに設定、マップなしの文言誤り)
- ATS判定: PE ヘッダが先頭300バイトより後ろにある DLL を判定できなかった(e_lfanew を読む方式に変更)
- BVE5/6 パス設定: ビット数が違う exe を選んでも起動パスに設定されていた

## 追加: 車両/マップファイルのエンコード手動切替(cbxVehicleEnc / cbxMapEnc)

従来は判定結果の表示のみ(Enabled=false、イベントなし)だった。
- 読込後に有効化され、UTF-8 / Shift_JIS を選ぶとそのエンコードで読み直す
- 指定はファイルごとに保持(タブ切替・車両/マップ切替で戻ってきても維持)、シナリオを開き直すとクリア
- 車両: 参照ファイルのパス・ATSプラグイン表示を読み直し
- マップ: 参照ファイルのパス・include 一覧・表示中のタブを読み直し。include 一覧はマップ本体と同じエンコードで読む
- BVE6コンバータ: 手動指定があればそのエンコードで読み、Shift_JIS ならヘッダに :shift_jis を付けて書き出す(記載漏れも補われる)
- あわせて修正: マップが1つだけのとき、ドロップダウンで選び直すと表示が消えたままになっていた。
  マップ切替時に前のマップの「開く」ボタンやグリッドが残っていた

## 追加: ファイルヘッダーによるエンコード判定を仕様準拠に

bvets.net の車両ファイル/マップファイルの仕様(他のファイル形式も共通)に合わせ、1行目のヘッダーで判定する。
- `BveTs Vehicle 2.00:shift_jis` のように、ファイル形式の直後のコロン以降をエンコード名として読む
- エンコード名の省略(コロンなし)は UTF-8
- 従来は1行目のどこかに "shift_jis" が含まれていれば Shift_JIS としていた(コメントや表記で誤判定し得た)
- shift_jis / shift-jis / sjis / cp932 等の表記ゆれは Shift_JIS とみなす。その他の名前(ISO_8859-1 等)も .NET が対応していればそのエンコードで読む
- 仕様外の記述は警告を表示(車両/マップはメッセージ、各タブのファイルはステータスバー)
  - 1行目にヘッダー(BveTs ...)がない
  - コロンの前後に空白がある
  - コロンの後にエンコード名がない / 未対応のエンコード名
- ヘッダー判定が誤っている(記載忘れ・保存ミス)場合は、従来どおりエンコードのコンボボックスで手動で切り替える

## 追加: シナリオファイルのエンコード手動切替(cbxScenarioEnc)

車両/マップと同じルール(まず1行目のヘッダーで判定 → 誤りがあれば手動で切替)。
- シナリオ読込後に有効化。UTF-8 / Shift_JIS を選ぶとそのエンコードで読み直す(車両・マップの表示も読み直し)
- 手動指定は同じシナリオのリロードでは維持。別のシナリオを開く・クリアすると解除
- ヘッダーが仕様外ならメッセージで警告
- 選択車両/マップで起動: 一時シナリオを読込時と同じエンコードで書き出し、ヘッダーのエンコード指定も
  実際のエンコードに合わせて書き換える(例: 記載漏れの Shift_JIS → "BveTs Scenario 2.00:shift_jis")。元ファイルは変更しない
- あわせて修正: シナリオ読込中のメッセージ(マップが見つからない等)が表示されないまま残ることがあった

## 追加: タブの選択位置を保持

- シナリオ・車両・マップを選び直しても、シナリオ/車両/マップ各タブの選択位置を保持する
  (従来は Reset と車両読込時に先頭タブへ戻していた)
- 読込後に選択中のタブの内容を読み直す(RefreshCurrentVehicleTab / RefreshCurrentMapTab)
- 保持はアプリ起動中のみ(終了時には保存しない)

## 動作確認のお願い(ビルド環境がなく未確認)
1. ビルド(新規ファイルは csproj に追加済み)
2. シナリオ一覧 → 各タブ表示 → エンコード切替
3. 「開く」「フォルダ」ボタン一式
4. 選択車両/マップで起動
5. (Ctrl+T)BVE6コンバータ → 復元
6. ヘッダに shift_jis のない Shift_JIS の車両/マップで、エンコードを Shift_JIS に切り替えて日本語パスが解決されること
7. 車両/マップの任意のタブを開いたまま、シナリオ一覧で別のシナリオを選び、同じタブのまま内容が更新されること
